## 2. RAG 模块的契约

> 提示：按 D4，RAG 的输出**不是**"几个文本片段"，而是"回 MySQL 取到的完整 case 列表 + 相似度分数 + `source_id`"。
> **RAG 不做任何判断**：它不决定结果够不够用、不决定要不要转人工、不改写结论。它只负责"给一个 query，返回最相关的 K 条完整 case"。
> 这一节写清楚了，Step 8 实现 RAG 时你就不需要再做任何设计决定。

- **输出结构（逐项列出字段名 + 含义）**：
- **Top-K 的 K = ?**：
- **为什么是这个 K**：
  > 提示：库只有 15~20 条。K=3 和 K=10 的差别是什么？K 太大会怎样（提示：LLM 上下文里塞进不相关案例，会诱导它编造关联）？K 太小会怎样？
- **相似度阈值**：设不设？设多少？低于阈值怎么办？
  > 提示：这是个真问题。不设阈值 → 哪怕全不相关也会返回 K 条，Agent 可能拿垃圾当依据；设阈值 → 阈值多少才合理，你现在**没有数据**能定。写出你的选择和"打算怎么在 Step 12 用评估数据校准它"。
